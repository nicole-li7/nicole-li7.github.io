how it works

One A*, five puzzles

The solver doesn't know what a puzzle is. Each puzzle is a node class that can list its neighbours, say whether it's the goal, and estimate how far it is from the goal. The same astarSolve works on the 8-puzzle, the 15-puzzle, Klotski (Huarong Pass), Missionaries & Cannibals and 8-Queens.

The heuristic is the whole game

A* always expands the position with the lowest moves so far + estimated moves left. For sliding puzzles the estimate is Manhattan distance: how many rows and columns each tile is away from home.

It never overestimates, so the answer is guaranteed to be the shortest. A weaker estimate like "misplaced tiles" is still correct but searches far more.

Accuracy vs speed

Multiply the estimate by 3 and A* turns greedy. It rushes toward whatever looks closest and finishes after looking at a tiny fraction of the positions, but the path it finds is often a few moves longer. Try "compare all four" above to see it.

Minimax with alpha-beta

Minimax assumes both players play perfectly: I pick the move with the best score, knowing you'll pick the reply with the worst score for me. Alpha-beta keeps track of the best score each side is already guaranteed and stops exploring a branch the moment it can't beat that.

Move ordering

Pruning works best when the strongest moves are tried first. Before searching, every move gets a quick one-step evaluation and the list is sorted best-first. That order decides how much of the tree gets skipped.

Four games, one engine

The minimax engine only sees an abstract GameState: its legal moves, what a move leads to, and a score. Tic-tac-toe, Gomoku, Othello and Chess each plug into it, with a small Windows GUI to play against it.
